# TARGET: Strava verification v2

- **Thing:** Trail League v2 adds Strava-based verification so eligible hiking activities—not manually typed numbers—can count toward individual and school standings.
- **Audience:** College outdoor-club members who want a fair way to compare hiking activity with people and clubs at other schools.
- **Requirements:** Let a user securely connect a Strava account; import eligible hiking activities for a defined season; use the Strava activity ID, distance, elevation gain, and activity date to calculate standings; prevent duplicate counting; distinguish Verified, Pending, and Rejected activities; never let a manual entry affect a verified leaderboard.
- **Guardrails:** Use a secure backend for OAuth credentials and tokens; never expose a Strava client secret in browser code or the repository. Request only the least access needed for activity verification, beginning with `activity:read`. Do not request activity-writing permission, collect route maps or GPS streams, display precise locations, imply official school affiliation, or claim verification makes cheating impossible. Support account disconnection and deletion of a user’s stored Trail League data. Work on a separate branch and wait for human review before shipping.
- **Experience:** Preserve Trail League’s national-park-signage and competitive-stat-sheet character. Clearly label entries as Verified, Pending, or Rejected; make verification status understandable before a rank changes; keep miles, elevation, and rank visually prominent.
- **Test:** I can connect a test Strava account in a secure development environment, import one eligible hiking activity, see it count once in individual and school standings, confirm a duplicate does not count twice, confirm a manual entry cannot affect verified standings, see Pending or Rejected feedback for an ineligible activity, and disconnect/delete the test account data.
